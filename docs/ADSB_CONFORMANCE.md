# ADS-B conformance

The host test suite reads skyBlip's ADS-B implementation 0.1.0 against RTCA DO-260B draft 4.2 (1090-WP30-18). This report covers the 282 receive-side clauses listed in [`firmware/test/adsb/clauses.txt`](../firmware/test/adsb/clauses.txt). The suite passed 199 cases and makes no claim on 88 (58 not implemented, 7 prose, 19 optional, 4 unmeasured): 5 cases it skipped and 83 clauses `clauses.txt` marks.

Each case names its file under `firmware/`. The cases under `protocols/adsb/test/conformance/` exercise the standalone decoder and report assembly. The device cases under `test/adsb/` test Bravo's driver against an LR2021 radio model, not physical radio hardware. A skipped case and a clause marked in `test/adsb/clauses.txt` give the reason they carry no claim. See [`firmware/test/adsb/README.md`](../firmware/test/adsb/README.md) for the receiver's scope and known gaps. Quoted prose comes from the test case's comment.

Generated by `scripts/conformance.py adsb` from the test run. CI checks that this report matches the suite. Change the test name or comment to update the report.

### DO-260B 2.2.3.2 ADS-B and TIS-B Message Baseline Format and Structures

- a DF17 frame is DF, CA, AA, a 56-bit ME and the PI parity (`protocols/adsb/test/conformance/test_formats.cpp`)

- the baseline fields sit at message bits 1, 6, 9, 33 and 89 (`protocols/adsb/test/conformance/test_formats.cpp`)

- DF17 is read and DF11, DF16, DF18 and DF19 are never read as DF17 (`protocols/adsb/test/conformance/test_formats.cpp`)
  > Each DF is read by its own rule, so no other format becomes a DF17 message.

- every CA code of Table 2-8 is carried as sent (`protocols/adsb/test/conformance/test_formats.cpp`)

- the AA field is the sender's 24-bit ICAO address (`protocols/adsb/test/conformance/test_formats.cpp`)

### DO-260B 2.2.3.2.1.6 "ME" Message, Extended Squitter

- the ME field's TYPE code picks the message its bits are read as (`protocols/adsb/test/conformance/test_formats.cpp`)

### DO-260B 2.2.3.2.1.7 "PI" Parity / Identity

- the PI field is the parity over an all-zero overlay (`protocols/adsb/test/conformance/test_formats.cpp`)
