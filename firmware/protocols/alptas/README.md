# protocols/alptas

The ALP-TAS air frame, 2024 protocol, message type 2: the frame (`frame.{h,cpp}`), its two cipher stages and their keys, its CRC-16 and the erasure repair a receiver runs before it, and the sync word it shares a window with ADS-L through. `version.h` names it in `kSpecification`. It builds and passes its tests with nothing but `protocols/common/` and doctest (`../README.md`).

`decode()` and `encode()` work on `Position`, the frame's own fields in its own units: the address, its type and, for a random address, the byte that names the next one, the urgency, the stealth and no-track flags, the highest version the sender reads, the fix time in quarter seconds, the aircraft type, the airborne code, the position in 1e-7 degree, the altitude in metres, the turn rate in centidegrees a second, speed and climb in decimetres a second, the track over ground in degrees, the three accuracy estimates, and the SIL, SDA and NIC. skyBlip maps those to an `AircraftObservation` in `core/protocol/alptas.*`: the ADS-L category an aircraft type is, the ADS-L address table an address type is, the G.1.2 state an airborne code is, and the ADS-L units. `decode()` needs the receiver's own position, because the frame carries only the low 20 bits of each coordinate step, and the UTC second the frame arrived in, because the mask stage is keyed on it.

## Public API

Everything is in namespace `skyblip::alptas`: `kSyncWord`, `kFrameBytes`, `crc()`, `set_crc()`, `crc_ok()`, `correct()`, `receive()`, `keyed_second()`, `address()`, `no_track()`, `Position`, `decode()`, `encode()`, `random_address_after()`, and `kVersion`, `kSpecification`.

## Where the ALP-TAS frame comes from

ALP-TAS is skyBlip's own reading of the 2024 protocol, put together from several public sources: the community's description of the frame, [pastebin.com/YB1ppAbt](https://pastebin.com/raw/YB1ppAbt), the open receivers that read it, and published descriptions of its fields. That reading was revised on 17 November 2026 in four places: the aircraft type is 5 bits, not 4, so types 16 to 19 (eVTOL and the three UAS classes) were read as 0 to 3. The address type is 2 bits, followed by a 2-bit urgency. A random address (type 0) is 32 bits, with its top byte at bit 40 and the random byte that names the next address at bit 32. The last byte, which every frame heard so far left at zero, is the SIL, SDA and NIC. `test/test_cassettes.cpp` replays ten frames byte for byte, each beside the receiver's second and place and what its sender said. Every scene is in the French Alps, from Annecy and Saint-Gervais to Barcelonnette, with the receiver in France too. Together they cover every address type, every urgency, both flags alone and together, a sender that cannot receive, the new aircraft types, rated and unrated frames, an aircraft on the ground, one circling and one high and fast. They are synthesized, not recorded on air: each scene was encoded once and pinned, and real receptions should replace them. Positions south of the equator, near the pole and below sea level are the round trips in `test/test_frame.cpp`. The frames `test/test_frame.cpp` pins guard the encoder against regressions.

## Two things an ALP-TAS frame is given before it is refused

`correct()` runs the erasure correction the ADS-L path has always had. §C.2.1 is Manchester, so a chip pair that decoded to neither symbol is an error whose position the receiver already knows: `wire::manchester_decode` marks it, skyBlip's `protocol::Frame` carries the map, and the frame CRC says which combination of those flips was transmitted. Both frames hand that search to `wire::repair` (`protocols/common/README.md`), which leaves a frame no combination repairs exactly as it arrived. Up to six marked bits, which is 64 combinations. Beyond that the burst is refused as damaged. The syndromes come out of the CRC's own linearity: flipping a data bit moves the check by `crc16_ccitt(that bit alone, init 0)`, and flipping a carried CRC bit moves it by the bit itself.

Until 2026-09-19 the ALP-TAS path checked the CRC and threw the frame away, so every burst with one dead chip pair was a `CRC` row while the same damage on an ADS-L frame was corrected and drawn. On a bench that difference is invisible, because nothing at -15 dBm has dead chips. At range it is receptions.

`keyed_second()` answers the question a `DEC` row could not. The key stage is `utc_s >> 4`, so the decrypt is correct for every second inside the sender's own 16-second block, and the 4 time bits inside the frame then pin the second to ±1. Both sides of that are cheap to exploit: decrypt once per block the search window reaches, check the fields a right key leaves in range, and the time bits name the sender's second exactly. The window is `kKeyWindowS`, 18 seconds, which is GPS-UTC: a receiver reporting GPS time instead of UTC is the one clock fault a device holding a valid fix can plausibly have, and a disagreement wider than that is not a clock, it is noise that framed.

## What a right key looks like

The cipher starts at byte 8. The address, its type, the urgency, the flags, the sub-type and the version go in clear, and every field after them reads as noise under the key of another 16-second block. The gate asks for version 3 and sub-type 0, but those say nothing about the key. A right key leaves the fix on a whole second, with the two quarter-second bits at 0. It also leaves the aircraft type at 19 or less, the NIC at 11 or less and the track under 360 degrees. Those four checks are about 3.6 bits, so a wrong key passes them about one time in twelve. A frame whose SIL, SDA and NIC are all 0, which is every sender heard so far, adds 8 bits of zeros, so it keeps the ±1 second the time bits are allowed. A rated frame has no such byte, so its time bits must name the receiver's second exactly, and `core/protocol/alptas.cpp` refuses one that places its sender beyond radio range. `keyed_second()` names another second only from an unrated frame, and only when one block in the window passes, because a rated frame cannot tell a wrong key from its own.

The frame is refused either way. What the search buys is the tape saying `KEY+18` instead of `DEC`, which is the difference between a support case about a radio and one about a receiver's time.
